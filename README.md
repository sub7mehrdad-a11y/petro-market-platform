# پلتفرم تحقیق و توسعه‌ی بازار

پلتفرم داخلی برای رصد روزانه‌ی قیمت جهانی و اخبار بازار جوش شیرین (سدیم بی‌کربنات)، سود پرک،
و کود آمونیوم سولفات، به‌همراه مخزن گزارش‌های تحقیق بازار.

## ساختار پروژه

```
.
├── scripts/
│   ├── price_intelligence_bot.py   # ایجنت روزانه‌ی قیمت (Claude API + web_search)
│   └── news_analysis_bot.py        # ایجنت روزانه‌ی اخبار/تحلیل (Claude API + web_search)
├── data/
│   ├── price_history.json          # خروجی تجمعی price_intelligence_bot.py
│   └── news_analysis_log.json      # خروجی تجمعی news_analysis_bot.py
├── reports/
│   ├── manifest.json               # فهرست متادیتای گزارش‌های آپلودشده
│   └── <کشور>/<فایل>.pdf|docx      # فایل‌های واقعی گزارش‌ها
├── web/                             # سایت Next.js (داشبورد + مخزن گزارش‌ها)
└── .github/workflows/daily_market_agents.yml   # اجرای خودکار روزانه
```

## چرا معماری «ایجنت جست‌وجوگر» به‌جای اسکرپر ثابت؟

نسخه‌ی اول یک regex-scraper بود که فقط یک صفحه‌ی ثابت (ECHEMI) رو می‌خوند. بعد از بررسی واقعی:

- هیچ منبع رایگان و بدون‌لاگینی برای قیمت **روزانه‌ی FOB** ترکیه یا هند پیدا نشد؛ فقط snapshotهای
  پراکنده (CIF هند، سیگنال‌های منطقه‌ای، قیمت داخلی چین) در دسترسن.
- سایت‌هایی مثل ECHEMI زیرساخت ضد-اسکرپینگ/فینگرپرینتینگ دارن؛ یک regex شکننده در برابرشون
  مقاوم نیست.

به همین دلیل، هر دو اسکریپت به‌جای selectors ثابت، از **Claude API + ابزار `web_search`** استفاده
می‌کنن — دقیقاً همون روشی که وقتی مستقیم از Claude گزارش بازار می‌خوای اتفاق می‌افته: هر روز چند
منبع رو هم‌زمان جست‌وجو می‌کنه، عدد/خبر رو با نوع و منبعش استخراج می‌کنه، و چون به ساختار HTML یک
صفحه‌ی خاص وابسته نیست، در برابر تغییر سایت‌ها مقاوم‌تره.

**محدودیت شناخته‌شده:** برای قیمت روزانه‌ی FOB ترکیه هیچ منبع رایگانی وجود نداره. اسکریپت این مورد
رو با `value: null` و توضیح در `note` ثبت می‌کنه؛ به‌عنوان جایگزین، سیگنال قیمت سود اش (ماده‌ی اولیه‌ی
مرتبط) رصد می‌شه. اگر روزی به یک منبع نیازمند لاگین (حتی رایگان) دسترسی پیدا کردید، این پلتفرم
نمی‌تونه خودش لاگین کنه — باید عدد رو دستی وارد کنید یا مستقیم به `data/price_history.json` اضافه‌ش
کنید.

## راه‌اندازی محلی

### اسکریپت‌های پایتون
```bash
pip install anthropic
cp .env.example .env   # و ANTHROPIC_API_KEY واقعی رو داخلش بذار
python scripts/price_intelligence_bot.py
python scripts/news_analysis_bot.py
```

### سایت
```bash
cd web
npm install
npm run dev
```
سایت روی `http://localhost:3000` بالا میاد و مستقیم از `../data` و `../reports` می‌خونه.

## اجرای خودکار روزانه (GitHub Actions)

1. این ریپازیتوری رو به گیت‌هاب push کنید.
2. در Settings > Secrets and variables > Actions، یک secret به اسم `ANTHROPIC_API_KEY` بسازید.
3. از تب Actions می‌تونید workflow «Daily Market Agents» رو دستی (`Run workflow`) هم تست کنید؛
   وگرنه هر روز ساعت 05:30 UTC (تابستان ایران ≈ 09:00) خودکار اجرا می‌شه و نتایج رو commit می‌کنه.

## اضافه‌کردن کشور/منبع/محصول جدید

- **منبع قیمت جدید:** به لیست `SEED_SOURCES` در [`scripts/price_intelligence_bot.py`](scripts/price_intelligence_bot.py)
  یک URL اضافه کنید؛ مدل خودش بررسیش می‌کنه. نیازی به نوشتن selector/regex نیست.
- **کشور جدید در جدول قیمت:** به `PRIORITY_COUNTRIES` در همون فایل اضافه کنید.
- **محصول جدید:** به لیست `PRODUCTS` در همون فایل و لیست `PRODUCTS` در
  [`web/app/reports/page.jsx`](web/app/reports/page.jsx) اضافه کنید.
- **منبع خبری جدید:** به `SEED_NEWS_SOURCES` در [`scripts/news_analysis_bot.py`](scripts/news_analysis_bot.py) اضافه کنید.
- **کشور جدید در مخزن گزارش‌ها:** به لیست `COUNTRIES` در [`web/app/reports/page.jsx`](web/app/reports/page.jsx)
  اضافه کنید (پوشه‌ی مربوطه‌اش موقع اولین آپلود خودکار ساخته می‌شه).

## قوانین ثابت (همیشه رعایت بشه)

- هرگز محتوای پشت پولوار/لاگین دور زده نمی‌شه.
- هر منبع حداکثر روزی یک‌بار خونده می‌شه.
- قیمت داخلی (ارز محلی) همیشه با برچسب `domestic` از FOB/CIF دلاری جدا نگه داشته می‌شه.
- در یادداشت‌های خبری، جمله‌ی کامل از منبع کپی نمی‌شه؛ فقط خلاصه + ذکر منبع.
- کلیدهای API فقط در `.env` (محلی، gitignore شده) یا GitHub Secrets — هرگز در کد.

## وضعیت فعلی / کارهای باقی‌مانده

- ✅ اعتبارسنجی منابع (فاز ۱)، نوشتن و تست منطق اسکریپت‌ها بدون کلید واقعی (فاز ۲)، وب‌سایت پایه (فاز ۳)
- ⏳ **تست با کلید API واقعی:** در این محیط `ANTHROPIC_API_KEY` در دسترس نبود؛ منطق parsing/ذخیره‌سازی
  با پاسخ‌های شبیه‌سازی‌شده تست شد، ولی اجرای واقعی با `web_search` رو باید با کلید خودتون (محلی یا
  از طریق `workflow_dispatch` در GitHub Actions) امتحان کنید.
- ⏳ **آپلود گزارش‌های واقعی برزیل/ترکیه:** مخزن گزارش‌ها آماده و تست‌شده‌ست ولی خالیه — از صفحه‌ی
  «گزارش‌های بازار» فایل‌های واقعی‌تون رو آپلود کنید.
- ⏳ **گزارش‌های زنده (فاز ۴):** بازتولید خودکار بخش تحلیلی گزارش‌ها بر اساس تغییر قیمت FOB/کرایه‌ی
  حمل هنوز پیاده‌سازی نشده — نیازمند طراحی جداگانه بعد از اینکه ساختار گزارش‌های واقعی برزیل رو دیدیم.
- ⏳ **پرسش‌وپاسخ هوشمند روی گزارش‌ها:** نیازمند استخراج متن از PDF/Word و یک لایه‌ی RAG؛ عمداً در این
  نسخه پیاده نشده تا اول با گزارش‌های واقعی شما ساختارش طراحی بشه.
